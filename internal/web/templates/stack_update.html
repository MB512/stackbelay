Update

The update recreates the running services with the newest images of their tags:

  1. Pull the images (docker compose pull) while the stack keeps running. If that fails, nothing is changed.
    2. {{- if .HasRepo}}
  2. Back up the stack: a snapshot while it runs, then stop it and take the final snapshot.
    3. {{- else}}
  3. Stop the stack. No backup is taken: the stack has no repository.
    4. {{- end}}
  4. Recreate the services with the new images (docker compose up) and wait up to 5 minutes until they run and, if they have a healthcheck, are healthy.
{{- if .HasRepo}}

If the services do not come up, the update is rolled back: the final snapshot is restored and the stack starts with the image versions it had before.

{{- else}}

Without repository a failed update is not rolled back. The stack is left as it is, not even the old images are started (a new version may already have converted data, which the old one could damage). Configure a repository to update with backup and rollback.

{{- end}}

Services built locally (build:) are not pulled. The stack must be running: an update only recreates running services.

Rollback

The rollback restores the final snapshot taken just before the update. In place it rewrites only the few files that changed since then instead of downloading and copying the whole stack, but nothing of the failed version is kept, and if the rollback itself fails half-way the stack stays stopped and partly restored.
