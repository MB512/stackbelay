Restore method

Switching over needs room for a complete second copy and downloads the whole snapshot, but the stack directory is untouched until the restored copy is complete, and the previous directory stays available for a manual rollback. In place downloads and rewrites only files that differ from the snapshot (same size and modification time count as unchanged) and deletes files that are not in the snapshot. Nothing of the current state is kept except the safety snapshot: if the restore fails half-way, the stack stays stopped and partly restored until you restore again.

Image versions

Pinning uses the image digests recorded in the snapshot's metadata.txt. Services built locally cannot be pinned and use compose.yml. If a pinned image can no longer be pulled, the restore is aborted and the current stack is started again. compose.yml is not changed: a later docker compose up uses the tags again.
